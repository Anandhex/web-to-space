Sixty-odd anchors across seven sections. Each one names the direction it is expected to take, so a wrong door is legible from the prose without opening the census. Hrefs that lead somewhere real lead to a page that names itself, so a door that opens on the wrong document says so.

1. Relative links → lateral ▸

A document beside this one, addressed relative to it. All four forms resolve against /link-test/index.html and all four are same-site, so all four are siblings: the reader turns their head, they do not climb or descend.

  • Chapter one — bare relative, no prefix.
  • Chapter two — explicit ./ prefix.
  • A nested page — one directory down.
  • The elements test page — ../ back up to the root.

Two edge cases in the same family: a relative href carrying a query string, and one carrying a fragment of ANOTHER document — the second is the case that must NOT collapse to here, because the fragment belongs to a page that is not this one.

2. Top-level links → lateral ▸ in prose, up ▴ in a nav

These are the same destinations the primary nav carries, written the same root-relative way, but sitting in prose instead. They should come out lateral, not up: the site's own root is a sibling document when a sentence mentions it and a parent when the site menu offers it, and the classifier reads the setting, not the slash.

  • /test-elements.html — a top-level document.
  • /link-test/chapter-one.html — root-relative to a sibling.
  • /link-test/deep/nested.html — root-relative, two deep.

The five links immediately above are the same destinations again, as a bare link run. Every one should be up — including the relative one and the external one, because ascent is decided by the setting and not by the href. That /test-elements.html appears twice on this page pointing two different ways is the whole test.

The absolute form of a same-origin URL belongs here too, and it is the one that most often goes wrong — an origin comparison that string-matches instead of parsing sends it down with the external links: the absolute localhost form of chapter two. It is same-site whenever the dev server is on that port, and off-site when it is not, which is itself worth seeing.

3. External links → down ▾

Another origin, reached deliberately. The WebXR Device API on MDN and the ARIA 1.2 specification are the two ordinary cases: absolute, https:, a different host.

  • A protocol-relative href — //host/path, which inherits the page's scheme and is the form that throws ERR_INVALID_URL when a base URL never arrives.
  • A plain http: href — off-site and downgraded.
  • A punycode host — the host comparison has to survive it.
  • An explicit non-default port — a different origin from the same host on 443.
  • A userinfo href — the host is still example.com.

And the malformed case, which has to land somewhere rather than throw: an href that will not parse is absolute in shape but fails new URL(), so it has an unknown locus, which the projection table sends down. (An href malformed in its SCHEME — ht!tp://… — is not absolute at all by the origin test's reckoning, and comes out a same-site relative path. That is a real seam, not a bug to fix here.)

4. Same-page fragments → here •

A pointer at something this view already draws, so it gets no body and no corridor — it lights the storey, tile or card the current view is already showing.

  • Back to section 1 — a bare fragment.
  • Back to section 3 — another one.
  • The absolute form of this page's own URL, plus a fragment — the shape a server-rendered table of contents emits. It must resolve to here, not to a lateral trip back to the document the reader is standing in.
  • A fragment that names nothing on this page — still here, but with no target to light.
  • [1] — a citation-shaped fragment: same-document wins for placement, and the citation flag survives beside it.

5. Operational links → inline, no mark

Following one of these hands off to another application, so no corridor could stand for it and none is drawn. They stay at their anchor.

  • Email someone
  • Call the number
  • A javascript: href
  • An href of # alone — an action on the page, not a fragment.
  • An empty href — the same.
  • A PDF — a download, which is an action even though it is same-site.
  • An external archive — a download too, and the extension wins over the origin.

6. Degenerate anchor text

These take the directions their hrefs imply; what they exercise is identity.ts, which has to synthesise a name because the anchor text identifies nothing. A door reading “here” tells the reader nothing about where it goes.

7. Density and overflow

Half the anchors on the web share a block with another anchor, which is why alignment alone cannot say which sentence points where. This paragraph is that case: it goes both to chapter one and to MDN's ARIA guide, one lateral and one down, from the same line of prose.

And a run long enough to exceed a side's window, so the lateral overflow path is exercised rather than argued about: one, two, three, four, five, six, seven.
